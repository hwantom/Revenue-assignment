1개 상품 행이 담긴 전표 20건, 2개 상품 행 45건, 3개 상품 행 30건, 4개 상품 행 5건입니다. 한 행의 구매 수량은 1개 또는 2개입니다. 가격은 부가세 포함 설정이며 할인은 품목별로 한 번만 차감합니다. 취소·환불, 외화, 복합결제는 포함하지 않았습니다.

## 의도적으로 다르게 만든 원본

- 원본 형식 5종을 각 20건씩 사용합니다. 상품명/Item/품목/제품명/Product처럼 키도 다릅니다.
- 날짜: YYYY-MM-DD, MM/DD/YYYY, YYYY.MM.DD, YYYY년 M월 D일, D Sep YYYY.
- POS_B의 슬래시 날짜는 월/일/년입니다. 브라우저가 자동 추정하도록 두면 안 됩니다.
- 시간: 24시간, AM/PM, 한글 시·분, HHmm, 초 포함 형식.
- 금액: 숫자 문자열, 원화 기호, 원, 쉼표, KRW 접두사.
- 상품·카테고리·결제수단·매장명에 한글/영문/띄어쓰기 별칭을 사용합니다.
- 카테고리 빈칸 12행은 상품 별칭으로 확인된 상품 마스터를 근거로 보완했습니다.
- 시간 미기재 5건은 null, 결제수단 미기재 3건은 ‘미확인’으로 유지했습니다. 두 조건의 중복 전표가 있으므로 단순 합산하지 않습니다.
- 중복 전표와 잘못된 금액은 주입하지 않았습니다. 중복 제거 실적이나 금액 오류 수정 실적을 임의로 표시하지 마세요.

## 정제본 계산과 검증

상품금액 = 수량 × 단가 - 품목 할인. 전표금액 = 해당 전표의 상품금액 합계.

정제 엑셀에서 상품금액 → 전표금액 → 요약 지표는 수식으로 연결됩니다. 전표 시트의 source_amount는 원본에서 읽은 고정 결제금액이며, amount_difference는 상품 합계와의 차이입니다. 제공본은 모두 0입니다. 편집해서 차이가 생기면 해당 칸이 강조됩니다.

JSON·CSV는 제공 시점의 정제 결과입니다. 엑셀에서 수정해도 JSON·CSV가 자동 변경되지는 않습니다. 원본 JSON을 바꾸고 재정제할 때는 패키지 폴더에서 `node source/clean_data.mjs`를 실행합니다. 이 명령은 정제 JSON·CSV·summary만 갱신하며 엑셀과 전표 PDF는 재생성하지 않습니다.

변환 이력은 값의 표기 변경과 결측 처리를 기록합니다. ‘4500’ → 숫자 4500처럼 표시가 같은 형변환과 항목명 대응은 변환 건수에 포함하지 않습니다. 항목명 대응은 source_profiles에서 확인합니다. 규칙별 건수는 중복될 수 있으므로 더해서 전표 수로 쓰면 안 됩니다.

### AI 전표 분석 (업로드 → 자동 분석)

PDF·JSON 전표를 끌어 놓으면 브라우저 안에서 **읽기 → 형식 인식(POS A–E) → 정제·검산 → 코멘트**까지 자동으로 처리하고, 결과가 바로 요약·매출 분석·전표 조회에 반영됩니다.

- 정제 규칙은 `source/clean_data.mjs`와 같습니다. 원본 PDF 100장을 이 판독기로 다시 읽어 정제 데이터와 전표·상품·변환 기록 수까지 100/100 일치하는 것을 확인했습니다.
- 이미 있는 전표번호는 중복으로 건너뜁니다. 새 전표는 `신규`로 표시되고, 이 브라우저에만 저장됩니다(AI 분석 → 비우기로 삭제).
- `samples/R101–R103.pdf`: 시연용 추가 전표(9/30 저녁, POS B·C·E 형식). 화면의 **샘플 3장** 버튼으로도 바로 체험할 수 있습니다. 다시 만들기: `python3 tools/make_sample_receipts.py --font-dir <Pretendard ttf 폴더>`
- 코멘트: 기본은 규칙 기반(객단가 대비·구성·시간대). **Claude API 키**를 넣으면 `claude-opus-5-5`가 한 줄 코멘트를 쓰고, 형식을 모르는 PDF는 Claude가 직접 읽어 구조화합니다. 키는 이 브라우저(localStorage)에만 저장되며 요청은 브라우저에서 Anthropic API로 바로 갑니다. 거절 시 서버 측 대체 모델(`fallbacks: "default"`)을 사용합니다.

- 상품·카테고리 필터에서는 해당 상품 행 금액만 합해 ‘거래당 선택 상품 매출’로 표시합니다.
